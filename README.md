## 人机协同个人复盘（王梦芸 本人撰写）

### 一、意图清晰度反思

今天两次任务结果和我预想的不一样，事后复盘发现，问题都出在我自己的提示词和需求描述不够严谨，不是缺模块，是细节考虑不到位。

第一次是程序排错的时候。我虽然写好了角色、目标、约束、验收标准，看着很完整，但我直接把浏览器报错的行号和内容原样复制当成了准确依据。结果AI排查后发现，报错里的行号对应的是CSS内容，根本不存在我以为的 resetAnimation 函数，等于我给的约束证据本身就是错的，直接带偏了排查方向。

后来我调整了需求，不再让AI"按照报错位置硬修"，而是明确交给它完整流程：先自己复现问题、自主定位bug、再给出修复方案。AI重新搭建了测试页面，一步步排查，最终实现控制台零报错。我也意识到：写需求不能只堆砌要素，还要保证我给的线索真实有效。

第二次是天体模拟预设功能的任务。这次我只写了角色、工程目标和技术约束，漏掉了验收标准，同时我自己也没发现新需求和旧设置存在冲突：我想要太空零重力效果，但之前设定的重力滑块范围是1~25，两者完全矛盾。

AI执行过程中主动发现了两处问题，并且自行补全了可量化的验收标准，比如动画补间需要逐帧连贯、参数刷新能正常读取原值，同时把滑块下限改成0，适配零重力场景。这件事让我很有收获：验收标准不是单纯用来考核结果的，它是给任务定的统一标尺，没有标准，AI只能靠猜测完成任务。之后写需求，我会额外加上一条：新功能与原有功能冲突时，明确允许修改、保留哪些内容，避免前后矛盾。

### 二、闭环控制反思

这次排查问题我总结出两个很实用的自查方法，都是实操中慢慢摸索出来的。

第一是不看画面观感，只看真实数据。之前双摆拖尾效果消失，页面没有任何报错，就是功能失效。我让AI逐帧检查轨迹数组的存储数据，最后找到问题：程序存储的是两个摆球的完整坐标数据，但渲染时只读取了单个点位的数值，导致出现大量NaN数值，画面直接不渲染。无声失效、无报错的bug，靠数据核对才能找出来。

第二是看不懂复杂公式，就看可验证的实测结果。双摆的微分方程、推导过程我完全看不懂，所以我不纠结理论，只要求AI给出可验证的证据。通过长时间运行监测机械能漂移，最终误差几乎为0，我才确认积分算法是准确的。包括零重力场景下周期显示无穷大而非报错NaN，也是靠边界条件验证判断功能正常。

对于AI的修复逻辑，我能理解核心思路，专业公式部分暂时无法完全吃透。比如阻尼效果原本是按帧数衰减，会受帧率波动影响，导致摆动速度不稳定，AI改成和真实时间绑定，解决了卡顿变速问题，这个逻辑我完全理解并认可。

协作中也不是完全依赖AI，我会主动纠正它的误判。比如重置功能结束后运行时间依旧上涨，AI一开始误以为是计时器没有清零，后面多次复测才更正。实际原因是页面工具响应存在十几秒延迟，属于正常现象。这让我明白：人机协作不能只看最终结论，我必须监督、核对它的取证过程，避免错误判断。

还有动画停滞的特殊问题，是浏览器页面折叠后台暂停导致的，我完全想不到这个排查角度，AI通过手动推进帧时钟测出补间曲线，解决了问题，也拓宽了我的排查思路。

### 三、主体地位反思

在整个人机协作流程里，我始终是最终决策者，AI只负责高效执行重复性工作，主次关系非常明确。

所有核心需求和项目标准都是我敲定的：滑块数量、摆长区间、阻尼参数上限、重置角度、页面深色固定风格、按钮高亮效果，还有功能取舍、项目推进节奏，全部由我决定。我也制定了固定的迭代规则：每次验收合格就打标签存档基线，期末累计成果用于答辩；验收绝不只看"完成"，必须提供逐条实测数据。

同时，所有AI无法替代的关键操作都由我完成：注册GitHub账号、创建仓库、配置修改访问权限、调试浏览器控制台、管理密钥凭证，这些核心权限和风险操作只能由我把控。

而AI主要承担重复、繁琐的技术工作：编写前端代码、查询API文档、搭建本地测试环境、逐帧采样测试数据、整理实验表格、编写提交记录和版本说明，还会把复杂的专业术语转化成通俗解释，降低我的理解难度。

### 总结

经过这几次实操，我真正理解了人机协同的核心：人定需求、定标准、定取舍、握有最终回滚决定权，AI负责高效落地、反复验证、细致执行。

我不需要担心AI试错出错，因为每一个版本都有存档基线，可以随时回退；我只需要对自己的需求描述、标准设定负责。后续我会继续优化自己的提示词逻辑，补齐验收标准、规避需求冲突，真正做到合理利用AI提升开发效率，同时牢牢守住人的主导地位。
